# Passkey 功能实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 为用户端增加最多两个 Passkey 的绑定、删除与无用户名免密登录，并为管理端增加按用户分组的 Passkey 查看和撤销页面。

**架构：** 使用 SimpleWebAuthn 完成浏览器与服务端的 WebAuthn 仪式，PostgreSQL 保存公钥凭据、稳定用户标识和一次性挑战。后端按 repository、class service、controller/route 分层；用户端封装浏览器 WebAuthn 调用，管理端以用户为分页单位返回嵌套密钥列表。

**技术栈：** Node.js 20+、Express、PostgreSQL、`@simplewebauthn/server ^14.0.3`、Vue 3、Element Plus、`@simplewebauthn/browser ^14.0.0`、Vitest。

**规格：** `docs/superpowers/specs/2026-10-15-passkey-design.md`

## 全局约束

- 生产环境 Node.js 必须为 20 或更高版本；部署前执行 `node --version`。
- RP ID 固定为 `tl.lolok.dpdns.org`，Expected Origin 固定为 `https://tl.lolok.dpdns.org`，不得从 Host 或转发请求头动态推导。
- 每名用户最多绑定 2 个 Passkey；数量限制必须由 PostgreSQL 事务和用户行锁保证。
- 注册使用 `residentKey: 'required'`、`userVerification: 'required'`、`attestationType: 'none'`；认证必须要求 User Verification。
- 挑战有效期固定为 5 分钟且只能消费一次；失败验证也不能复用同一挑战。
- 新增和删除 Passkey 都必须校验当前密码；密码登录始终保留。
- 后端只保存公钥和必要元数据，不在接口或日志中暴露公钥、Credential ID、Challenge 或浏览器完整响应。
- 所有新增文件和方法补充职责、关键参数与核心分支注释；包含多个方法和内部状态的服务使用 class。
- 不修改 `docs/requirements.md` 和 `docs/api.md`，除非用户另行确认。
- 功能实现与测试最终整理为一笔中文提交；任务间只做验证检查点，不保留零碎过程提交。
- 修改任何 `server/**/*.js` 后，交付时提醒用户重启服务器，不自行启动服务器。

## 重点审查项

- 两个注册完成请求并发到达时，只有一个能占用最后一个名额，另一个返回上限错误；Task 2 的并发测试固定此行为。
- 同步型 Passkey 的签名计数器可能持续为 0，服务端应接受合法的 0→0；Task 3 的认证测试固定此行为。
- 用户取消浏览器系统窗口产生 `NotAllowedError` 时不显示安全失败；Task 5 的组件测试固定此行为。
- 管理端按密钥名称搜索时仍以用户为分页单位并返回该用户的全部密钥；Task 4 的服务测试固定此行为。
- 反向代理环境中请求 Host 与固定 Origin 不一致或缺失时，验证仍只使用显式配置；Task 3 的配置与验证测试固定此行为。
