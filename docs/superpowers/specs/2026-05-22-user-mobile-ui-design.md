# 用户端移动端页面改版设计方案

## 背景

当前用户端已经具备购买、登录、订阅生成、工单、帮助中心等完整功能，但移动端体验仍偏桌面站思路，主要问题包括：

- 登录后仍以侧边栏思维组织页面，不够像移动端 App。
- 个人中心承载的信息过多，订阅、续费、订单、帮助混在同一页，重点不够突出。
- 套餐展示页信息清楚，但移动端购买氛围和转化感偏弱。
- 系统公告放在外部区域，曝光不足，用户通常不会主动查看。
- `CF IP 优选` 和 `生成订阅链接` 是实际使用链路中的关键动作，但在新的页面构思中必须继续保持高优先级曝光。

本次方案先不修改业务逻辑与接口，优先重构用户端前端页面结构和视觉层级，重点提升移动端体验。

## 目标

- 将登录后用户端改造成更像 App 的移动端体验。
- 使用底部导航替代移动端侧边栏作为主入口。
- 将首页改造成会员面板型工作台，优先展示状态和高频动作。
- 明确保留 `一键优选 CF IP` 与 `生成订阅链接` 两个关键功能的高可见入口。
- 优化未登录套餐展示页，提高移动端购买转化感。
- 将系统公告并入登录后首页，提高公告曝光率。
- 保持现有业务流程和接口能力基本不变，优先做页面组织优化。

## 非目标

- 本阶段不改后端接口和数据库结构。
- 本阶段不新增公告系统、推荐系统、埋点系统等新能力。
- 本阶段不修改支付流程本身，只调整套餐展示与购买承接页视觉。
- 本阶段不先做管理端 UI 改版。

## 已确认的视觉方向

- 整体风格采用“卡片运营型”。
- 登录后首页采用“会员面板型”布局，而不是营销型堆叠首页。
- 底部导航保留 4 个一级入口：
  - `首页`
  - `订阅`
  - `帮助`
  - `我的`
- `工单` 不单独放到底部导航中，收纳进 `我的` 页面。
- 页面顶部不再重复显示与底部导航等价的当前栏目标题，避免信息重复。
- `系统公告` 不再作为外部独立关注区，而是并入登录后首页。

## 信息架构

### 未登录区域

- `/`
  - 作为移动端套餐展示与购买入口页
  - 主职责是展示套餐、引导购买、承接新用户转化
- `/login`
  - 作为登录页与“选中套餐后的注册/支付承接页”

### 登录后区域

- `/user`
  - 登录后首页
  - 展示套餐状态、流量进度、高频操作、公告摘要
- `/user/subscription`
  - 订阅页
  - 展示订阅链接、复制入口、节点列表、导入说明
- `/user/help`
  - 帮助中心列表
- `/user/help/:id`
  - 帮助文章详情
- `/user/profile` 或现有个人中心承接页能力
  - 由“我的”页承接服务入口、账户状态、订单与工单跳转
- `/user/tickets`
  - 不作为一级导航，但从“我的”进入

说明：

- 若现有路由结构不想大改，可保留现有路由名称，只调整页面职责与展示内容。
- 移动端底部导航只负责四个一级页面，其他页面通过页面内入口跳转。

## 页面设计

### 1. 登录后首页

首页定位为“会员面板型工作台”，以老用户回访高频任务为中心。

首页内容顺序建议如下：

1. 顶部欢迎区
   - 显示欢迎语、用户头像占位、轻量状态说明
   - 不再单独显示“首页”这类重复标题
2. 套餐状态卡
   - 当前套餐
   - 已用流量 / 总流量
   - 流量进度条
   - 账户状态
3. 高频动作卡
   - `一键优选 CF IP`
   - `生成订阅链接`
4. 订阅使用流程提示
   - 优选 CF IP
   - 生成订阅链接
   - 复制导入客户端
5. 系统公告卡
   - 仅展示最新 2-3 条公告
   - 列表项可点击进入公告详情或跳转帮助/公告页

设计原则：

- 先状态，后动作，再内容。
- `CF IP 优选` 和 `生成订阅链接` 必须在首页首屏或少量滚动内可见。
- 这两个动作需要明确加入 `1 / 2` 的步骤标记，降低新用户理解成本。
- 首页删除“服务与帮助”卡片，避免首页入口过多、重点分散。
- 公告必须进入首页可视区，避免成为低关注内容。
- 首页不再放大表格，不做长列表堆叠。

### 2. 订阅页

订阅页从现有个人中心中拆出，专门承接订阅相关操作。

核心内容：

- `一键优选 CF IP`
- `生成订阅链接`
- 通用订阅链接展示
- Clash 订阅链接展示
- 对应复制按钮

设计原则：

- 订阅页主区域只保留 `CF IP 优选` 和 `生成订阅链接` 两个核心按钮。
- 去掉“快捷操作”和“推荐流程”等重复说明区块，减少视觉噪音。
- 对首次使用用户，页面通过 `1 / 2` 步骤标记表达“先优选，再生成”的顺序。
- 两个按钮建议使用编号文案或步骤徽标：
  - `1. 一键优选 CF IP`
  - `2. 生成订阅链接`
- 按钮下方必须保留生成后的订阅链接展示区，以及通用订阅、Clash 订阅各自的复制按钮。
- 避免与首页重复展示大量账户信息和额外说明区块。

### 订阅关键交互规则

为保持与现有代码逻辑一致，并继续降低误操作，`CF IP 优选` 和 `生成订阅链接` 的交互应遵循以下规则：

1. `生成订阅链接` 按钮默认不因为“尚未优选”而长期置灰。
2. 当用户未完成 `CF IP 优选` 就点击 `生成订阅链接` 时：
   - 允许点击
   - 弹出明确提示：`请先进行 CF IP 优选`
   - 不进入真正的生成流程
3. 当用户已完成 `CF IP 优选` 并点击 `生成订阅链接` 后：
   - 按钮进入加载态或置灰态
   - 文案可改为 `生成中...`
   - 在请求完成前不可重复点击
4. 当订阅链接成功生成后：
   - 更新订阅链接展示内容
   - 恢复按钮可点击状态
5. 若生成失败：
   - 恢复按钮可点击状态
   - 给出失败提示

这套规则的目的：

- 保持现有业务习惯，避免新老用户认知断裂
- 防止重复点击引发重复请求
- 通过提示而不是静态置灰，明确告诉用户下一步该做什么

### 3. 帮助页

帮助页保留现有内容型页面定位，但移动端应加强可读性。

建议优化方向：

- 顶部分类筛选更适合横向滑动
- 文章列表使用卡片化布局
- 缩短首屏说明文字
- 帮助详情页加强段落间距和代码块可读性

帮助页继续承担：

- 新手教程
- 客户端使用说明
- 常见问题
- 公告详情承接页（如果复用帮助详情结构）

### 4. 我的页

“我的”页从原来的“什么都塞在个人中心”调整为“服务聚合页”。

页面内容建议：

1. 账户信息卡
   - 邮箱
   - 当前套餐
   - 账户状态
2. 我的服务宫格
   - 续费套餐
   - 工单支持
   - 客户端下载
   - 使用教程
3. 常用管理列表
   - 订阅链接管理
   - 订单记录
   - 帮助中心
   - 退出登录

设计原则：

- 强化“设置/服务中心”的感觉。
- 工单通过“我的”进入，而不是占用底部一级导航。
- 减少冗余文本，突出功能入口。

### 5. 未登录套餐展示页

未登录首页要从“桌面网站展示页”提升为“移动端购买页”。

页面结构建议：

1. 顶部品牌与价值说明
   - 一句话说明产品卖点
   - 小型标签说明支持设备/客户端
2. 套餐分类筛选
   - 推荐
   - 入门
   - 高流量
   - 长期
3. 套餐卡片列表
   - 套餐名
   - 简述
   - 价格
   - 流量
   - 时长
   - 适合人群
   - 直接购买按钮
4. 次级内容
   - 公告、常见问题、购买说明等放到套餐区后方

设计原则：

- 卡片内直接完成主要理解和购买决策。
- 推荐套餐应有视觉强调。
- 尽量压缩滚动成本，首屏就让用户理解差异。

### 6. 登录/注册承接页

现有 `Login.vue` 已具备“带套餐信息注册支付”的流程，建议只做视觉升级，不改业务结构。

可优化点：

- 套餐信息卡更卡片化、更像确认订单
- 支付方式按钮更具辨识度
- 移动端输入区间距更舒展
- 注册态与登录态样式区分更明确

## 导航设计

### 移动端

使用固定底部导航替代移动端侧边栏主导航：

- `首页`
- `订阅`
- `帮助`
- `我的`

导航规则：

- 当前页面高亮仅通过底部导航表达。
- 页面顶部不重复显示“首页 / 订阅 / 我的”这类同义标题。
- 二级页面如工单详情、帮助文章详情、节点详情等，不进入底部导航主层，只保留返回路径。

### 桌面端

桌面端可继续保留侧边栏或逐步统一到新的信息架构，但本次主要以移动端为优先。

建议：

- 桌面端先兼容新的页面职责划分
- 不要求第一阶段完全复制移动端底部导航样式

## 系统公告策略

系统公告调整为首页内容模块，而不是外部独立主关注点。

具体策略：

- 首页展示最新 2-3 条公告摘要
- 公告卡片标题清晰，避免被误认为普通帮助文章
- 每条公告可进入详情页查看完整内容
- 公告模块位置在“高频操作”之后、“页面底部”之前

这样做的原因：

- 用户登录后的首页是高频回访页，公告曝光明显高于独立公告区
- 公告与账户状态、订阅操作放在同一个工作台中，用户更容易感知

## 组件与实现建议

本次实现建议尽量复用现有页面与接口能力，不做大规模业务改造。

### 可优先复用

- `client-user/src/views/user/Layout.vue`
  - 改造成支持移动端底部导航的新布局容器
- `client-user/src/views/user/Profile.vue`
  - 拆分首页职责与“我的”职责，并保留 `CF IP 优选`、`生成订阅链接` 的首页入口
- `client-user/src/views/user/Subscription.vue`
  - 承接完整订阅页，并强化 `CF IP 优选` 与 `生成订阅链接` 的主操作区
- `client-user/src/views/Home.vue`
  - 承接未登录套餐展示页升级
- `client-user/src/components/RenewDialog.vue`
  - 保留逻辑，升级视觉样式
- 现有帮助中心与工单页面
  - 继续作为二级页使用

### 实现边界

- 优先做布局重组和样式升级
- 尽量不改接口字段
- 尽量不改后端数据结构

## 响应式原则

- 移动端优先设计，桌面端兼容适配
- 主要断点延续现有习惯：
  - `< 768px`：移动端
  - `768px - 1024px`：平板
  - `> 1024px`：桌面

重点要求：

- 移动端底部导航固定，内容区预留底部安全空间
- 长列表与卡片之间保持更大的点击区域
- 复制按钮、续费按钮等核心操作必须单手易点

## 测试与验证

本阶段为设计方案与文档阶段，不做代码变更验证。

进入实施阶段后建议验证：

- `client-user` 构建通过
- 移动端 375px / 390px / 430px 宽度可正常浏览
- 底部导航无遮挡
- 首页公告在首屏或少量滚动后可见
- `CF IP 优选` 与 `生成订阅链接` 在首页和订阅页都可快速触达
- 未优选时点击生成按钮，会收到“请先进行 CF IP 优选”的明确提示
- 生成订阅过程中按钮进入置灰/加载状态，完成后恢复
- 订阅复制按钮与续费按钮在移动端交互清晰
