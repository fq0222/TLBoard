# 管理端 Tailwind CSS 响应式改造设计

## 1. 背景与目标

管理端当前使用 Vue 3、Vite 与 Element Plus。桌面端布局和组件视觉已经稳定，但全局布局缺少移动端断点，大量页面还包含固定宽度筛选控件、密集数据表格、多列表单和固定宽度弹窗，导致窄屏下出现内容挤压或横向溢出。

本次改造目标是在保持现有桌面端视觉与业务行为不变的前提下，引入 Tailwind CSS 作为响应式布局工具，使管理端在 375px 及以上移动设备上能够完成导航、浏览、筛选、分页和常用管理操作。

## 2. 范围

### 2.1 包含范围

- 为 `client-admin/` 引入 Tailwind CSS 及其构建配置。
- 改造管理端全局侧栏、页头和内容区域的响应式行为。
- 调整全部管理端页面的工具栏、卡片栅格、表单、弹窗、分页和长内容展示。
- 为高频数据页面提供移动端卡片视图。
- 为低频或复杂数据表格提供受控横向滚动，并在移动端隐藏次要列。
- 增加可自动验证的响应式结构测试，并执行现有测试和生产构建。
- 对 375px、390px、768px、1024px、1440px 视口进行人工视觉与交互回归。

### 2.2 不包含范围

- 不修改后端接口、数据库结构或管理端路由地址。
- 不替换 Element Plus 组件库。
- 不重新设计桌面端配色、字号、间距、卡片、表格或导航风格。
- 不在本次改造中拆分现有大型业务页面或重构 API、Store 等业务代码。
- 不为移动端创建独立路由或独立数据请求。

## 3. 技术方案

采用 Tailwind CSS 与 Element Plus 共存的渐进式方案：

- Element Plus 继续提供表格、表单、弹窗、分页、日期选择器和消息提示等交互组件。
- Tailwind CSS 负责响应式显隐、Flex/Grid 排列、宽度、间距和溢出控制。
- 现有 scoped CSS 默认保留；只有已被 Tailwind 清晰替代且验证无回归的布局规则才允许删除。
- Tailwind 不得通过全局样式重置改变 Element Plus 或现有桌面端元素的默认视觉。配置时关闭 Preflight 或采用效果等价的样式隔离措施。
- Tailwind 工具类使用统一前缀，避免与现有 `.container`、`.header`、`.content` 等业务类名冲突。
- 桌面端以当前实现为基线，主要响应式切换点为 768px；复杂双栏弹窗和编辑器允许在 960px 处提前切换为单列。

## 4. 全局布局

### 4.1 桌面端

- 视口宽度大于 768px 时继续显示固定侧栏。
- 展开宽度保持 240px，折叠宽度保持 64px。
- 主内容区的左边距继续跟随侧栏展开状态。
- 页头高度、面包屑、管理员信息和工单提醒按钮保留当前视觉。

### 4.2 移动端

- 视口宽度不大于 768px 时，侧栏脱离主内容排版并作为宽度 280px 的抽屉显示。
- 页头展示菜单按钮、当前页面标题和必要的账户操作；空间不足时隐藏面包屑中的次要内容和管理员名称。
- 侧栏打开时显示遮罩，并锁定页面背景滚动。
- 点击遮罩、点击导航项、路由变化或按下 Escape 时关闭侧栏。
- 主内容区左边距归零，页面水平内边距缩小，但不得小于 12px。
- 工单提醒按钮保留，并适配移动设备安全边距，避免覆盖分页和主要操作按钮。

## 5. 页面响应式规则

### 5.1 工具栏和页面标题

- 桌面端保持现有横向排列。
- 移动端标题、说明和操作按钮允许换行。
- 搜索框、选择器和日期筛选器在移动端使用可用宽度的 100%。
- 多个按钮优先换行，不压缩文字；主要操作保持清晰可见。

### 5.2 卡片和统计区

- 三列、四列统计区在移动端降为一列。
- 两列详情区在移动端降为一列。
- 服务器和家宽 IP 等已有卡片页沿用当前业务结构，只补齐窄屏宽度、间距和长文本换行规则。

### 5.3 表单

- 桌面端继续使用当前固定标签宽度。
- 移动端长表单切换为顶部标签或效果等价的单列结构。
- 输入框、选择器、日期选择器、数字输入框和上传区域不得超出容器。
- 同一语义的一组输入控件可保留同行，但在 375px 下无法完整显示时必须换行。

### 5.4 弹窗和抽屉

- 桌面端保留现有弹窗宽度。
- 移动端弹窗宽度使用 `calc(100vw - 24px)` 或效果等价的安全宽度。
- 长弹窗设置视口内最大高度，内容区内部滚动，底部主要操作保持可达。
- Users 和 Blogs 等双栏编辑内容在 960px 以下切换为单列。

### 5.5 分页

- 桌面端保留当前分页布局。
- 移动端居中显示分页，并减少非必要信息和页码按钮数量。
- 分页不得导致整个页面产生横向滚动。

## 6. 数据表格策略

桌面端始终保留现有 Element Plus 表格。所有移动端展示继续复用同一份响应式数据、格式化方法和业务操作方法，不增加重复 API 请求。

### 6.1 移动端卡片化页面

以下页面在不大于 768px 的视口显示卡片列表，在更大视口显示原表格：

- 用户管理：展示邮箱、套餐、流量、到期时间、状态和主要操作。
- 订单管理：展示订单号、用户、套餐、金额、支付状态、时间和主要操作。
- 工单管理：展示标题、用户、状态、创建时间、未读状态和查看操作。
- 公告管理：展示标题、置顶状态、启用状态、创建时间和编辑/删除操作。
- 套餐管理：展示套餐名称、价格、流量、期限、销售状态和主要操作。
- CF IP 管理：展示地址、端口、状态和编辑/删除操作。
- 服务器详情用户列表：展示用户标识、在线状态、启用状态、到期时间、流量和主要操作。

卡片内容只改变呈现方式，不改变权限判断、确认弹窗、提交状态和事件处理逻辑。

### 6.2 横向滚动页面

以下页面保留表格，在移动端放入明确的横向滚动容器，并按重要性隐藏次要列：

- 邮件管理中的收件人、日志和统计表格。
- 邮件活动列表。
- 邮件模板列表。
- 资源管理列表。
- 系统设置中的管理员与 Telegram 绑定列表。
- 推广明细列表。
- 流量统计弹窗中的用户表格。

滚动容器必须限制在内容区内部，不能把页面整体撑宽；操作列应保持可访问，无法固定时允许用户横向滚动到达。

## 7. 页面实施分组

### 7.1 第一组：基础设施和外壳

- Tailwind 构建配置和全局样式入口。
- `Layout.vue` 移动端导航、遮罩、滚动锁定和内容区域。
- Login、NotFound 和 Dashboard 的基础响应式布局。

### 7.2 第二组：核心卡片化页面

- Users、Orders、Tickets、Announcements、Plans、CfIps、ServerDetail。
- 优先建立可复用的移动端字段行和操作区样式，避免各页面出现不同的间距和层级。

### 7.3 第三组：卡片、详情和内容页面

- Servers、HomeProxies、Feedback、TicketDetail、TrafficStats。
- 重点处理信息栅格、图表容器、长文本、详情操作区和弹窗。

### 7.4 第四组：复杂表单和低频表格

- Email、EmailCampaigns、EmailSender、EmailTemplates、Resources、Blogs、Referrals、Settings。
- 重点处理标签页、编辑器、预览区、上传控件、长表单、抽屉和横向滚动表格。

## 8. 状态与交互

- 移动端卡片视图与桌面表格共享 loading、empty、pagination 和筛选状态。
- 加载中不得同时显示旧列表的可操作按钮。
- 空数据状态继续使用现有 Element Plus Empty 或当前页面的空状态。
- 删除、退出等破坏性操作继续使用现有确认流程，不因卡片化跳过确认。
- 提交中禁用规则、成功提示和错误提示保持现有行为。
- 页面切换后恢复顶部滚动位置，并关闭移动端导航。

## 9. 可访问性要求

- 移动端菜单按钮具有可读的 `aria-label`，并暴露展开状态。
- 遮罩可点击关闭；侧栏可通过 Escape 关闭。
- 新增的卡片操作必须使用真实按钮或链接，不使用不可聚焦的普通元素模拟。
- 键盘焦点样式不得被 Tailwind 或自定义样式移除。
- 触控操作目标建议不小于 44px；密集操作至少保留足够间距以避免误触。
- 颜色不得成为状态的唯一表达方式，继续保留文字或标签。
- 长文本可换行或省略时，应保证仍有查看完整内容的路径。

## 10. 测试与验证

### 10.1 自动化验证

- 增加 Tailwind 配置测试，验证 Preflight 隔离、内容扫描路径和全局入口存在。
- 增加 Layout 结构测试，验证移动端菜单按钮、遮罩、关闭条件和响应式类存在。
- 为卡片化页面增加结构测试，验证桌面表格和移动端卡片同时存在、共享数据源并调用原操作方法。
- 为横向滚动页面增加结构测试，验证滚动容器和移动端宽度规则存在。
- 运行 `client-admin/test/` 下全部 Node 测试。
- 执行管理端生产构建；如 terser 环境异常，则按项目约定使用 `npx vite build --minify esbuild` 复核代码可构建性。

### 10.2 人工回归

在 375px、390px、768px、1024px 和 1440px 视口检查：

- 登录、退出和路由导航。
- 侧栏打开、关闭、遮罩与背景滚动。
- 页面标题、筛选工具栏和分页。
- 表格与移动端卡片切换。
- 新建、编辑、查看和删除弹窗。
- 长表单、日期选择器、上传控件和富文本/Markdown 预览。
- 图表尺寸变化和窗口缩放。
- 页面是否出现非预期的整体横向滚动。

## 11. 验收标准

- 1024px 和 1440px 下现有桌面布局、配色、组件尺寸和主要交互没有可见回归。
- 375px 和 390px 下全局导航和所有管理端路由可访问。
- 页面主体不产生非预期横向滚动；被明确列为横向滚动的表格只在自身容器内滚动。
- 关键数据页面在移动端使用可读的卡片列表，所有原有主要操作可完成。
- 弹窗不超出视口，内容可滚动，主要操作按钮可到达。
- 所有现有管理端测试与新增响应式测试通过。
- 管理端生产构建成功，并保留完整测试与构建日志用于交付。

## 12. 提交与实施约束

- 不创建或切换分支，不创建 Git worktree。
- 设计、规格和实施计划归入一笔中文文档提交。
- 功能实现与测试整理为少量可追溯的中文提交，不按修正次数制造零碎提交。
- 未经用户确认不得推送远程仓库。
- 本次不修改 `server/**/*.js`，无需因本次前端改造重启后端服务。
