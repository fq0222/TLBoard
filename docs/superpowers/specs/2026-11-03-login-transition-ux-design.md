# 登录跳转体验优化设计

## 意图

消除两类首次加载割裂感：套餐页点击“登录”后应立即离开套餐页；登录接口成功后，按钮应保持原有 loading 图标，并在用户中心真正完成导航后再收到成功提示。

## 范围

- 密码登录与 Passkey 登录统一等待路由导航完成。
- 登录按钮在导航期间保持 loading，文字维持原有“登录”或“Passkey 登录”。
- 登录页在浏览器空闲期预加载用户中心布局与首页组件。
- `/login` 路由同步加载轻量登录壳，完整登录表单作为壳内异步子组件加载。
- 登录表单加载期间展示与登录页结构接近的骨架和 loading；加载失败展示保留当前 URL 的刷新重试状态，以重建 Vite 资源缓存。
- 预加载属于性能增强，失败不得影响登录、提示或路由跳转。
- 不调整后端接口、首页业务请求和生产服务器静态资源配置。

## 方案选择

1. 仅延后成功 Toast：改动最小，但首次进入仍需完整等待目标 chunk。
2. 等待导航并预加载目标页面（采用）：同时改善状态反馈和实际等待时间，改动集中在登录页及一个小型预加载工具。
3. 重构首页为骨架屏和后台数据刷新：收益更大，但范围远超本次快速体验修复。

### 套餐页进入登录页

1. 仅在套餐页空闲预加载登录页：保持首页轻量，但用户立即点击时仍可能停留在套餐页等待。
2. 将完整登录页同步打入首屏：保证点击后显示完整表单，但会让所有套餐页访客承担表单、Element Plus 与 Passkey 依赖。
3. 同步轻量登录壳承载异步表单（采用）：套餐页点击后立即进入 `/login` 并显示骨架，完整表单优先加载；表单挂载后再空闲预加载用户中心。

## 交互语义

- 认证请求期间按钮显示原有 loading。
- 认证成功至路由完成期间，两种登录入口继续锁定并显示 loading 图标，按钮文案不变化，防止重复认证。
- 路由完成后显示“登录成功”；路由失败则不显示成功 Toast，并恢复登录入口。
- 登录页空闲预加载不显示额外 UI，不阻塞公开设置、推广归因或 Passkey 能力探测。
- 套餐页点击“登录”时，路由只等待同步登录壳，不能等待完整 `Login.vue` chunk。
- 登录壳保留原查询参数；异步表单成功后直接替换骨架，不增加浏览器历史记录。
- 登录表单是首要加载资源；`Layout.vue` 与 `Profile.vue` 继续由表单挂载后的空闲任务加载，避免争抢冷缓存带宽。
