# CF IP 泛域名测速改造设计

**目标**

将用户端 CF IP 优选测速从直接访问 `https://IP:443/cdn-cgi/trace` 改为访问 `https://<ip-转横杠>.gotl.xyz/cdn-cgi/trace?rel=<随机数>`，提升浏览器侧测速的真实性，避免 HTTPS 直连 IP 带来的证书与 SNI 干扰，同时保留现有“最多推荐 5 个优选 IP”的交互语义。

**现状问题**

- 当前前端直接请求 `https://IP:443/cdn-cgi/trace`，浏览器环境下容易受到证书、SNI 和直连 IP 策略影响。
- 当前失败判定存在误差：请求异常后若耗时超过阈值，可能仍被当成有效延迟写入结果。
- 当前超时时间 5000ms 偏长，会拖慢用户等待时间，也会让明显较慢的节点进入候选范围。
- 当前排序以“丢包率 + 平均延迟”为主，虽然稳，但建立在目标 URL 可真实反映可达性的前提上；这一前提目前不够可靠。

**改造方案**

采用“域名测速 + 双次采样 + 失败硬淘汰”的浏览器测速方案：

- 测速 URL：
  - IPv4：将 `.` 替换为 `-`，拼接成 `https://104-16-0-1.gotl.xyz/cdn-cgi/trace?rel=<随机数>`
  - 每次请求都带随机参数，避免浏览器缓存影响结果
- 并发限制：
  - 继续沿用前端动态工作池，并发上限保持 10
- 单 IP 采样次数：
  - 每个 IP 测 2 次
- 超时控制：
  - 每次请求必须使用 `AbortController`
  - 1500ms 硬超时，到时立即中断并判定为失败
- 计时方式：
  - 使用 `performance.now()` 计算从发起 `fetch` 到请求完成的综合 HTTP 延迟
- 失败判定：
  - `fetch` 抛错、超时、中断，统一视为失败
  - 失败样本不写入延迟数组，不再折算成“慢但成功”的结果
- 推荐策略：
  - 过滤掉 2 次都失败的 IP
  - 先按成功次数降序排序
  - 再按平均延迟升序排序
  - 返回最优前 5 个 IP

**兼容性边界**

- 本次方案以 IPv4 的 `*.gotl.xyz` 映射为前提；当前候选池仍可能包含 1 个 IPv6，需要明确处理策略。
- 推荐做法是：
  - 仅对 IPv4 使用新域名测速逻辑
  - IPv6 在本轮推荐中不强制保留名额，也不参与 `gotl.xyz` 域名变换
  - 若后续需要支持 IPv6，应单独定义域名映射规则，而不是在本次改造中猜测实现
- 因此，本次改造默认面向 IPv4 优选链路；现有候选池分发逻辑可暂时保留，但测速函数需对不支持的新链路类型给出明确失败或跳过策略。

**文件影响**

- `client-user/src/utils/cf-ip-test-config.js`
  - 调整测速超时配置
- `client-user/src/utils/cf-ip-optimizer.js`
  - 调整推荐排序与过滤策略，移除对“丢包率优先”的依赖
- `client-user/src/views/user/CfOptimize.vue`
  - 替换测速 URL 生成与失败处理逻辑
- `client-user/src/views/user/Profile.vue`
  - 同步一键优选页面内联测速逻辑
- `client-user/src/views/user/Subscription.vue`
  - 同步订阅页面内联测速逻辑
- `client-user/test/cf-ip-optimizer.test.js`
  - 更新推荐策略测试
- 如有需要，可新增一个浏览器测速辅助工具文件，避免三个页面重复维护同一套测速实现

**错误处理**

- 任一单次请求失败不应中断整个优选流程，只影响当前 IP 的成功次数与平均延迟。
- 若所有候选 IP 都失败，页面应维持当前“没有可用 IP”提示语义，不应自动回退到旧逻辑。
- 若 `gotl.xyz` 泛域名链路未生效，结果会集中失败；这类情况应通过现有前端错误提示向用户暴露。

**测试策略**

- 单元测试：
  - 覆盖“成功次数优先、平均延迟次之”的排序规则
  - 覆盖 2 次都失败时不进入推荐结果
  - 覆盖数量不足 5 个时仅返回有效结果
- 页面回归：
  - 验证三个页面中测速与推荐行为一致
  - 验证“测试完成后自动按新规则推荐前 5”文案与行为不偏离现有交互
- 构建验证：
  - 执行用户端构建，确认无语法和依赖错误

**不在本次范围**

- 不修改服务端 CF IP 池分发逻辑
- 不修改用户优选结果的保存接口
- 不引入服务端代理测速
- 不在本次改造中额外调整 UI 文案与展示结构，除非为解释新失败逻辑必须微调
