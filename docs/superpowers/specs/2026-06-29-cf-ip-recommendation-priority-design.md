# CF IP 自动推荐优先级调整设计

## 目标

调整用户端 CF IP 自动推荐规则：仅从丢包率不高于 20% 且存在有效平均延迟的测速结果中选择候选，再按平均延迟从低到高推荐最多 5 个 IP。完整测速结果仍照常展示，不隐藏丢包率超过 20% 的结果。

## 推荐规则

自动选择前 5 个 IP 时依次执行：

1. 排除未成功连通、平均延迟无效或丢包率大于 20% 的结果。
2. 将剩余结果按 `avgLatency` 从低到高排序；丢包率在合格区间内不再参与排序。
3. 若存在合格 IPv6，优先保留平均延迟最低的 1 个 IPv6。
4. 其余名额优先使用排序靠前的 IPv4；IPv4 不足时使用剩余 IPv6 补足。
5. 合格结果不足 5 个时选择全部合格结果；没有合格结果时提示“没有丢包率不高于 20% 的可用线路”。

丢包率等于 20% 的结果属于合格候选。

## 代码边界

复用 `client-user/src/utils/cf-ip-optimizer.js` 中的推荐函数作为唯一规则入口。用户资料页、订阅页和 CF IP 优选页的自动推荐均调用该函数，避免页面内各自维护筛选和排序逻辑。

CF IP 优选页继续展示全部测试结果，手动选择能力和最多选择 5 个 IP 的限制保持不变。后端接口、数据库和测速参数均不调整。

## 验证

采用测试驱动方式覆盖：

- 丢包率为 20% 的结果可以进入推荐，21% 的结果被排除。
- 合格候选按平均延迟排序，而不是按丢包率排序。
- 无有效平均延迟或未成功连通的结果被排除。
- IPv6 保留及 IPv4 优先补位规则不变。
- 没有合格候选时返回空推荐结果。
- 三个自动推荐入口均使用统一推荐函数。
