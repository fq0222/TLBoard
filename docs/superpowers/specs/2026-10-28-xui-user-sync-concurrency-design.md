# 3X-UI 六小时用户同步并发设计

## 背景与目标

[`server/jobs/handlers/sync-xui-users.js`](../../../server/jobs/handlers/sync-xui-users.js) 的六小时巡检任务当前按“服务器串行、单台服务器内用户串行”执行。大量用户叠加网络高峰时，总耗时接近所有用户远程请求耗时之和。

本次目标是复用项目已有的 [`runWithConcurrency()`](../../../server/utils/concurrency.js)，将单台服务器内的用户同步改为最大并发 `10`，同时控制对 3X-UI、数据库连接池和远程网络的瞬时压力。

## 目标

- 3X-UI 3.4.2+ 和旧版面板同步分支都支持用户并发。
- 单台服务器内最多同时同步 10 个用户。
- 单个用户失败不阻断同批其他用户。
- 保持服务器之间串行，避免“服务器数 × 用户数”的乘法并发。
- 保持六小时周期、启动延迟、手动触发入口、统一调度器去重语义不变。

## 非目标

- 不并发处理多台服务器。
- 不修改 `runWithConcurrency()` 的实现。
- 不新增依赖、数据库表或迁移。
- 不调整 3X-UI 写入锁、重试队列及同步任务执行周期。
- 不把并发数做成环境变量；本次沿用项目其他 3X-UI 场景的固定上限 `10`。

## 方案对比

### 方案一：仅并发 3.4.2+ 用户

改动最少，但旧版面板仍保持串行，两个分支行为不一致。

### 方案二：单台服务器内并发用户，服务器保持串行（采用）

两个面板分支都使用受限任务池处理用户。该方案能直接消除主要瓶颈，同时维持每台服务器的快照、统计和收口边界。

### 方案三：全局并发“服务器 × 用户”

理论吞吐更高，但会同时向多台面板发出大量请求，放大网络高峰期压力，并要求重构服务器快照和统计流程，风险高于当前需求。

## 设计

### 并发边界

- 在任务模块中定义 `XUI_USER_SYNC_CONCURRENCY = 10`。
- `runXuiSync()` 继续按服务器顺序调用 `syncUsersToServer()`。
- `syncUsersToServer()` 仍只执行一次 `getInbounds()`、人数缓存更新、节点快照刷新和 `last_check_at` 更新。
- 用户级远程查询、配置读写和 3X-UI upsert 进入 `runWithConcurrency()`。

### 3X-UI 3.4.2+ 分支

抽取“在当前服务器同步单个 canonical 用户”的内部方法。该方法负责：

1. 从本轮 inbound 快照识别远端用户，必要时回退 clients API。
2. 读取并解析本地服务器级凭证。
3. 为本服务器的各 inbound 保存一致的节点配置。
4. 比较远端状态；一致时跳过，不一致时调用 `upsertServerClient()`。
5. 返回成功、跳过或失败结果，供外层汇总。

外层通过 `runWithConcurrency(users, 10, worker)` 执行。现有 `upsertServerClient()` 的“服务器 + 邮箱” advisory lock 继续保护同一用户的并发写入；最多 10 个写任务占用专用数据库连接，低于默认连接池上限 20。

### 旧版面板分支

旧版面板继续按 inbound 顺序处理，避免不同 inbound 的流程被额外重排；每个 inbound 内使用同一个并发工具并发用户，最大并发 10。

每个用户任务继续复用当前的节点邮件名、凭证生成、`upsertUniqueClient()` 和日志语义。因为 inbound 外层仍串行，整个单台服务器的用户同步并发不会叠加超过 10。

### 结果与错误处理

- 使用 `runWithConcurrency()` 的 all-settled 结果语义，确保单项抛错不终止任务池。
- 单用户业务失败与异常都带用户邮箱、服务器名称及必要的 inbound 上下文记录。
- 外层汇总成功、跳过和失败数量，并输出单台服务器完成日志。
- 某台服务器整体初始化或 `getInbounds()` 失败时，保持现有行为：记录错误并继续下一台服务器。
- 统一调度器仍禁止同名六小时任务或手动任务重入。

## 测试与验证

扩展 [`server/test/test-xui-sync-users-job.js`](../../../server/test/test-xui-sync-users-job.js)，至少覆盖：

1. 3.4.2+ 分支处理超过 10 个用户时，观测最大并发恰好为 10。
2. 旧版面板分支处理超过 10 个用户时，最大并发不超过 10。
3. 单个用户抛错或返回失败，不影响其他用户完成。
4. 多台服务器仍按顺序执行，不产生服务器级并发。
5. 一致用户继续跳过远端写入，凭证选择和快照复用行为不变。

实施后运行并展示日志：

```bash
node server/test/test-concurrency.js
node server/test/test-xui-sync-users-job.js
node server/test/test-managed-server-counts.js
node server/test/test-admin-xui-user-sync.js
```

## 风险控制

- 并发日志会交错：所有用户日志保留用户、服务器和 inbound 上下文。
- 3X-UI 在高峰期承压：固定上限 10，不使用无上限 `Promise.all()`。
- 数据库连接池被占满：新版远端写入最多占用 10 个 advisory-lock 专用连接，给其他请求保留容量。
- 用户同步与其他业务同时写入：继续依赖已有的服务器用户锁和唯一约束，不削弱原有一致性保护。

## 验收标准

- 六小时任务在单台服务器上可同时处理最多 10 个用户。
- 新旧面板同步分支均不再逐用户完全串行。
- 任一用户失败不会阻断其余用户。
- 多服务器仍串行，任务防重入及触发周期不变。
- 所列测试全部通过，并展示完整测试日志。
