# 家宽 routing 离线服务器待清理设计

## 目标

修复用户修改家宽 IP 绑定时被离线旧服务器阻塞的问题，同时保留远程 routing 的后续清理依据。绑定流程严格保持“先删除旧 routing，再绑定新服务器”。

## 范围

- 用户端服务器下拉列表只展示在线服务器。
- 离线旧服务器允许跳过远程删除，并记录为待清理。
- 在线旧服务器删除失败时中止操作，不绑定新服务器。
- 用户下一次修改绑定时顺带重试在线的待清理服务器。
- 家宽套餐到期时合并清理当前绑定和待清理服务器，离线服务器允许跳过。
- 管理员删除服务器时，从当前绑定和待清理列表中移除该服务器 ID。

不增加服务器恢复后的独立定时清理任务，不修改订单、支付、流量统计和订阅生成模块。

## 数据结构

在 `user_home_proxy_routes` 新增：

```sql
pending_cleanup_server_ids TEXT NOT NULL DEFAULT '[]'
```

- `server_ids` 保存当前有效绑定。
- `pending_cleanup_server_ids` 保存本地已解除绑定、但因服务器离线而未删除远程 routing 的服务器 ID。
- 两个字段都按正整数数组解析、去重并序列化。
- 当前重新选中的服务器必须从待清理列表排除。

新增幂等迁移 `server/db/migrations/036-home-routing-pending-cleanup.js`，并同步更新全新安装使用的表结构。

## 用户端展示

后端可选服务器仍只查询 `xui_servers.status = 1`。打开修改弹窗时，只回填“当前绑定 ID 与在线服务器 ID 的交集”，因此离线服务器不会出现在选择框中。

当前配置区域仍可通过 route 详情展示原服务器名称和状态，便于用户了解离线旧绑定。

## 修改绑定流程

设当前绑定为 `currentServerIds`，历史待清理为 `pendingCleanupServerIds`，新选择为 `nextServerIds`。

1. 先校验 `nextServerIds` 数量为 1 到 2，且全部存在并在线；失败时不执行任何远程修改。
2. 清理目标为“本次从当前绑定中移除的 ID”与“历史待清理 ID”的并集，再排除 `nextServerIds`。
3. 逐个处理清理目标：
   - 服务器记录不存在：视为无需远程清理，从待清理集合移除。
   - `status != 1`：跳过远程删除，加入待清理集合，不阻塞换绑。
   - 在线且 routing 删除成功：从待清理集合移除。
   - 在线但 routing 删除失败：立即返回失败，不开始绑定新服务器，也不写入新的绑定结果。
4. 只有清理阶段没有在线删除失败时，才为 `nextServerIds` 同步 routing。
5. 新服务器全部同步成功后，保存 `server_ids = nextServerIds` 和剩余的 `pending_cleanup_server_ids`，并开始现有五分钟冷却。
6. 若存在离线跳过项，接口仍返回成功，同时返回其服务器信息供前端显示警告提示。

远程 routing 删除保持幂等；重试删除已经不存在的用户规则视为成功。若一次清理多个在线服务器时发生部分成功，不实现远程回滚，后续重试依靠幂等删除收敛，这与现有远程批量同步的失败边界一致。

## 手动删除绑定

手动删除复用同一清理规则：在线删除失败则失败，离线则进入待清理列表。清理阶段成功后将 `server_ids` 清空；待清理列表非空时保留数据库记录，但用户端将空的 `server_ids` 视为“暂无当前绑定”。两个数组都为空时删除记录。

## 套餐到期

保持现有“在线远程清理失败则本轮过期清理失败”的规则，并增加离线跳过：

- 清理目标为 `server_ids + pending_cleanup_server_ids`。
- 在线删除失败：保留现有失败和下轮重试语义，不完成本轮过期处理。
- 离线：跳过远程删除并保留在 `pending_cleanup_server_ids`，但不阻止套餐按现有流程标记过期。
- 完成后清空 `server_ids`；待清理列表为空则删除 route 记录，否则保留仅含待清理信息的记录。
- 不新增服务器恢复后的定时重试；若用户以后续费并再次修改绑定，将再次处理待清理 ID。

## 管理员删除服务器

管理员删除 `xui_servers` 记录时，在同一数据库事务中：

1. 从所有 route 的 `server_ids` 中移除目标 ID。
2. 从所有 route 的 `pending_cleanup_server_ids` 中移除目标 ID。
3. 删除两个数组都为空的 route 记录。
4. 删除 `xui_servers` 记录。

服务器已经被管理员删除，因此不再尝试远程清理。数组字段无法使用普通外键级联，必须显式维护。

## 错误与提示

- 新选择服务器离线：沿用“选择的服务器不存在或当前离线”。
- 在线旧服务器删除失败：返回失败服务器列表，前端提示绑定失败，不调用新服务器绑定。
- 离线旧服务器被跳过：绑定成功，前端提示“新服务器绑定成功；原服务器当前离线，routing 将在后续操作中继续清理”。
- 失败操作不开始新的冷却；成功换绑继续使用现有五分钟冷却。

## 验证重点

- 离线服务器不出现在选择框，旧离线 ID 也不会被回填。
- 在线旧服务器删除失败时，新服务器没有收到任何同步请求。
- 离线旧服务器会进入待清理列表且新服务器可以成功绑定。
- 待清理服务器恢复在线后，在下一次修改时先删除，再绑定新服务器。
- 套餐到期遇到在线删除失败仍失败，遇到离线服务器则跳过并保留待清理记录。
- 管理员删除服务器时，两类数组和空 route 记录在同一事务内完成清理。
