# 3X-UI 用户流量迁移脚本设计文档

## 概述

创建一个独立的 Node.js 脚本，用于将源 3X-UI 服务器的用户流量迁移到目标服务器，实现服务器合并场景下的流量数据保留。

## 需求背景

### 使用场景
- 服务器合并：将多台 3X-UI 服务器的用户合并到一台服务器
- 流量保留：确保用户已使用的流量数据不丢失
- 数据一致性：避免流量数据重复计算或丢失

### 核心需求
1. 从源服务器读取所有用户的流量数据
2. 显示汇总统计和详细列表供用户确认
3. 确认后执行迁移，将流量累加到目标服务器
4. 避免流量数据丢失

## 技术设计

### 文件位置
```
server/test/migrate-xui-traffic.js
```

### 依赖关系

### 数据结构

#### 用户流量数据
```javascript
{
  email: 'user@example.com',      // 用户邮箱（匹配标识）
  uuid: 'xxx-xxx-xxx',            // 用户UUID
  inbound_id: 1,                  // 节点ID
  inbound_remark: '节点名称',      // 节点备注
  traffic_used: 1073741824,       // 已用流量（字节）
  traffic_limit: 10737418240,     // 流量限制（字节）
  enable: true,                   // 是否启用
  expiry_time: 1234567890         // 到期时间
}
```

### 核心函数

#### 1. getAllUsersTraffic(xuiService)
获取服务器所有节点的所有用户流量数据。

**参数：**
- `xuiService`: XuiService 实例

**返回：**
```javascript
{
  success: true,
  users: [...],           // 用户流量数据数组
  totalTraffic: 1234567890, // 总流量（字节）
  userCount: 150          // 用户数量
}
```

**实现逻辑：**
1. 调用 `xuiService.getInbounds()` 获取所有节点
2. 遍历每个节点，解析 `settings` 获取用户列表
3. 对每个用户调用 `xuiService.getClientTrafficsByEmail()` 获取流量
4. 汇总数据并返回

#### 2. showSummary(sourceUsers, targetUsers)
显示迁移前的汇总统计。

**输出内容：**
- 源服务器用户数
- 目标服务器用户数
- 匹配用户数（邮箱相同）
- 新用户数（目标服务器不存在）
- 总流量

#### 3. showDetailedList(users)
显示用户流量详细列表。

**输出格式：**
```
序号 | 邮箱                | 节点       | 已用流量  | 流量限制  | 状态
-----|--------------------|-----------|---------|---------|-----
1    | user1@example.com  | 节点1-香港 | 1.5 GB  | 10 GB   | 启用
2    | user2@example.com  | 节点2-美国 | 3.2 GB  | 50 GB   | 启用
```

#### 4. migrateTraffic(sourceUsers, targetXuiService)
执行流量迁移。

**参数：**
- `sourceUsers`: 源服务器用户数据数组
- `targetXuiService`: 目标服务器 XuiService 实例

**实现逻辑：**
1. 遍历源服务器用户
2. 在目标服务器查找匹配用户（邮箱匹配）
3. 如果匹配：
   - 获取目标服务器用户的当前流量
   - 计算新流量：`目标流量 + 源流量`
   - 调用 `targetXuiService.updateClient()` 更新流量
4. 如果不匹配：
   - 记录为跳过用户
5. 返回迁移结果

#### 5. main()
主函数，协调整个迁移流程。

**流程：**
```
1. 解析命令行参数（源服务器ID、目标服务器ID）
2. 从数据库获取服务器信息
3. 连接源服务器和目标服务器
4. 读取源服务器用户流量
5. 读取目标服务器用户流量（用于匹配统计）
6. 显示汇总统计
7. 显示详细列表
8. 等待用户确认
9. 执行迁移
10. 显示迁移结果
```

### 错误处理

#### 连接失败
- 提示错误信息
- 退出脚本，返回错误码 1

#### 用户匹配失败
- 记录跳过的用户
- 在结果中显示跳过数量

#### 流量更新失败
- 记录失败的用户和原因
- 继续处理其他用户
- 在结果中显示失败数量

#### 所有错误汇总
```
迁移结果汇总：
- 成功: 145
- 失败: 5
- 跳过: 0

失败详情：
- user1@example.com: 流量更新失败 - 连接超时
- user2@example.com: 流量更新失败 - 用户不存在
```

### 命令行参数

```bash
node server/test/migrate-xui-traffic.js --source <源服务器ID> --target <目标服务器ID>
```

**参数说明：**
- `--source` 或 `-s`: 源服务器 ID（数据库中的 xui_servers.id）
- `--target` 或 `-t`: 目标服务器 ID

**示例：**
```bash
node server/test/migrate-xui-traffic.js --source 1 --target 2
```

### 配置要求

#### 数据库配置
脚本需要从数据库读取服务器信息，使用现有的 `config.js` 配置。

#### 服务器信息
从 `xui_servers` 表读取：
- `id`: 服务器 ID
- `name`: 服务器名称
- `api_url`: API 地址
- `api_username`: API 用户名
- `api_password`: API 密码

### 安全考虑

#### 流量数据保护
- 迁移前显示详细信息供用户确认
- 使用事务确保数据一致性
- 记录迁移日志便于问题排查

#### 错误恢复
- 如果迁移过程中断，已处理的用户不会重复处理
- 可以重新运行脚本继续未完成的迁移
- 失败的用户会记录在日志中
