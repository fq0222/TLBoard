# VMQ 监控端在线检查设计

## 目标

用户注册购买和续费使用 VMQ 支付前，先查询 VMQ 服务端状态。仅当监控端明确在线时继续创建支付订单；监控端离线或状态查询失败时，提示“暂时无法支付，请联系客服”。余额续费不受此限制。

## 状态判定

复用 `server/integrations/vmq/vmq-service.js` 已有的 `getState()` 请求，并在同一模块新增无状态方法 `isMonitorOnline()`：

- VMQ 响应的 `code` 转为数字后必须等于 `1`。
- `data` 必须存在。
- `data.state` 必须严格等于字符串 `"1"`。
- 状态为 `"0"`、`"-1"`、数字 `1`、缺少字段、响应结构异常、请求超时或网络错误时均返回 `false`。

该方法只负责将 VMQ 状态归一化为布尔值，不负责生成用户端业务响应。

## 支付流程

### 注册购买

`server/services/user/auth-service.js` 在完成用户、套餐和库存等现有业务校验后，调用 `isMonitorOnline()`。检查应发生在密码哈希、用户写入和本地待支付订单创建之前。

监控端不可用时，抛出现有格式的业务异常：

- HTTP 状态：`503`
- 业务码：`5004`
- 提示：`暂时无法支付，请联系客服`
- 不创建用户记录
- 不创建本地订单
- 不调用 VMQ 创建订单接口

### 续费支付

`server/services/user/renew-service.js` 保持余额支付分支不变。只有非余额支付通过现有用户、套餐、续费资格和确认重置等校验后，才调用 `isMonitorOnline()`。

监控端不可用时使用与注册购买相同的 HTTP 状态、业务码和提示，并且：

- 不创建本地续费订单
- 不调用 VMQ 创建订单接口

余额支付不查询 VMQ 状态，即使 VMQ 离线或不可访问也可正常完成。

## 错误处理

状态查询采用失败关闭策略。`isMonitorOnline()` 捕获 VMQ 请求异常并返回 `false`，避免网络错误泄露为通用 500 响应。注册和续费服务将 `false` 转换为统一、可面向用户展示的 503 业务错误。

现有 VMQ 创建订单失败、人工输入金额风险检查和订单过期处理保持不变。

## 测试

沿用 `server/test/` 下可直接通过 Node.js 执行的断言脚本风格：

1. VMQ 状态响应为 `code: 1` 且 `data.state: "1"` 时判定在线。
2. `state` 为 `"0"`、`"-1"`、数字 `1` 或响应结构异常时判定离线。
3. 状态请求抛出异常时判定离线。
4. 注册购买在监控端离线时返回指定业务错误，且不写入用户或订单。
5. VMQ 续费在监控端离线时返回指定业务错误，且不创建订单。
6. 余额续费不调用状态检查并保持原有成功行为。

实现完成后运行相关新增测试以及现有续费、支付测试脚本，并展示完整测试日志。由于会修改 `server/**/*.js`，交付时提醒用户重启后端服务器，但不自行启动。

## 变更范围

预计仅修改 VMQ 集成、注册服务、续费服务和对应测试脚本。不修改前端：现有前端会直接展示后端返回的 `message`。不新增依赖、不新增配置、不修改数据库和 API 文档。
