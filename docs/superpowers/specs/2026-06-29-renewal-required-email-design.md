# 套餐续费提醒邮件设计

## 目标

当用户首次进入需要续费的状态时，系统只尝试发送一次提醒邮件：

- 限时套餐：流量达到上限或套餐到期时触发。
- 不限时流量套餐：仅流量达到上限时触发。
- 同一次权益周期内，定时任务重复执行、3X-UI 禁用同步失败或邮件发送失败均不得再次尝试。
- 用户续费成功后进入新的权益周期，允许下次再次触发提醒。

## 方案选择

在 `users` 表保存本权益周期的提醒尝试状态：

- `renewal_notice_attempted_at BIGINT`：首次尝试提醒的秒级时间戳。
- `renewal_notice_reason VARCHAR(50)`：触发原因，取值为 `traffic_limit` 或 `expired`。

该状态比使用 `email_logs` 去重可靠，因为邮件日志会被定期清理，且邮件发送失败或配额不足时不一定产生成功日志。单独建立通知事件表虽然更便于扩展，但当前需求只有一个提醒周期，属于不必要的复杂度。

## 状态与数据流

### 流量超限

流量同步任务完成流量入库和二次校验后，在用户由启用变为禁用时原子写入：

- `enabled = 0`
- `traffic_used_at = 当前时间`
- `disable_reason = 'traffic_limit'`
- 当 `renewal_notice_attempted_at IS NULL` 时，写入提醒尝试时间和原因

数据库更新结果同时返回本次是否取得提醒发送资格。只有首次状态转换取得资格的调用才发送邮件。已禁用用户进行 3X-UI 补偿同步时不发送。

### 限时套餐到期

到期检查继续只选择 `plan_type = 'timed'`、`expire_at <= now` 且仍启用的用户。成功执行到期禁用时，以同样方式原子写入提醒尝试状态，原因记录为 `expired`，随后仅由取得资格的调用发送邮件。

`plan_type = 'lifetime'` 的不限时流量套餐不参与到期查询，因此不会产生时间到期提醒。

### 续费重置

支付完成更新用户权益时清空：

- `renewal_notice_attempted_at = NULL`
- `renewal_notice_reason = NULL`

清空操作与订单支付、用户权益更新处于同一数据库事务中。无论续费是否重置已用流量，只要续费成功，新权益周期都可在未来再次发送一次提醒。

## 邮件发送

新增独立的共享续费提醒邮件服务，复用现有 Brevo 客户端、每日邮件配额、站点地址、邮件日志和开通提醒邮件的绿色卡片视觉风格。

邮件主题固定为：

`【天澜大陆消息】亲爱的 {{username}}，您的魔法传送能量已经耗尽！`

其中 `username` 使用现有规则，从邮箱 `@` 前提取。邮件正文根据原因显示：

- `traffic_limit`：套餐流量已经耗尽，需要续费后继续使用。
- `expired`：限时套餐已经到期，需要续费后继续使用。

正文展示账号、套餐名称、已用流量、流量上限和到期时间，并提供用户中心入口。所有用户数据进入 HTML 前必须转义。

提醒标记在调用外部邮件服务前写入。每日额度已满、Brevo 返回失败、配置缺失或发生异常均视为已经尝试，不安排重试，也不影响禁用及 3X-UI 同步流程。发送成功时沿用 `email_logs` 写入成功日志。

## 并发与失败处理

- 用户状态锁负责串行化同一用户的禁用和续费状态变化。
- 数据库条件更新负责保证提醒资格只被领取一次。
- 邮件发送位于状态锁和数据库状态转换之后，避免慢速外部请求长期占用用户状态锁。
- 3X-UI 同步失败仍进入现有补偿队列，但不得重新触发邮件。
- 邮件异常只记录日志，不向上抛出并中断定时任务。

外部邮件服务无法与 PostgreSQL 组成原子事务，因此采用“先持久化尝试状态、后调用邮件服务”的至多一次语义。若进程在两步之间退出，该周期不会补发；这符合“只尝试一次、不重试”的要求。

## 数据库迁移

新增幂等迁移脚本，为 `users` 表补充两个字段，并同步更新新数据库建表结构。迁移可重复执行，已存在字段时跳过。

生产部署顺序：

1. 执行数据库迁移。
2. 部署后端代码。
3. 重启后端服务。

## 测试范围

后端测试至少覆盖：

- 流量首次超限时领取一次提醒资格并发送。
- 本地已禁用后的 3X-UI 补偿重试不发送邮件。
- 到期的限时套餐首次禁用时发送。
- 不限时流量套餐不进入到期禁用和到期提醒。
- 邮件发送失败或每日配额不足后不再尝试。
- 续费成功清空提醒状态，下一权益周期可再次发送。
- 并发或重复调用只能有一次取得提醒资格。
- 邮件主题、用户名替换、原因文案和 HTML 转义正确。

验证使用 `server/test/` 下的相关测试脚本，并保留完整测试日志。
