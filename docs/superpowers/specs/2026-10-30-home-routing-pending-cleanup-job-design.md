# 家宽 routing 待清理服务器定时任务设计

## 目标

每天北京时间 12:00 清理 `user_home_proxy_routes.pending_cleanup_server_ids` 中仍未删除的用户 routing。服务器离线或远端删除失败时保留服务器 ID，等待下一次任务重试。

## 范围

- 新增独立的 `node-cron` 定时任务，到点后只将清理工作加入现有 XUI 后台队列，不在服务启动时补执行。
- 查询存在待清理服务器 ID 的家宽 routing 记录。
- 复用现有 3X-UI routing 删除能力，只清理 `pending_cleanup_server_ids`，不改变当前绑定流程。
- 增加服务层、仓储层和定时任务测试。

不修改前端、不增加数据库字段、不改变套餐到期逻辑，也不扩展历史 `home_proxy_tag` 保存机制。

## 方案选择

考虑了以下方案：

1. cron 到点后加入现有 `xuiJobScheduler`，由 XUI 后台队列与流量统计、用户同步、XUI 任务同步等任务串行执行；业务判断仍集中在家宽 routing 服务层。
2. cron 到点后直接调用家宽 routing 服务。代码更少，但会与其他后台 XUI 任务并发修改或读取服务器配置。
3. 引入持久化重试队列。可提供更细粒度重试，但超出本次每天清理残留记录的需求。

采用方案 1，复用现有 XUI 队列的 FIFO、同名任务合并、前台请求空闲等待和访问后冷却能力。保留现有按用户互斥，作为定时清理与用户手动绑定、解绑之间的保护；XUI 队列不替代该互斥。

## 执行流程

1. 使用 cron 表达式 `0 12 * * *`，时区固定为 `Asia/Shanghai`。
2. cron 到点后调用 `xuiJobScheduler.schedule('home-routing-pending-cleanup', handler)`；注册时和入队时都不直接执行清理业务。
3. 队列按 FIFO 执行清理任务；同名任务已经运行或等待时由调度器合并，不重复入队。
4. 任务真正执行时查询 `pending_cleanup_server_ids` 非空的路由记录，并取得用户邮箱、当前 `server_ids` 和 `home_proxy_tag`。
5. 每个用户处理前再次读取当前记录；如果某个待清理 ID 已出现在当前 `server_ids` 中，则不删除其远端 routing，并从待清理集合中排除，避免误删重新绑定的服务器。
6. 对待清理服务器分类：
   - 在线：调用现有 routing 删除逻辑。
   - 离线：不调用 3X-UI，保留 ID。
   - 已不存在：移除本地待清理 ID。
7. 在线服务器删除成功后移除对应 ID；删除失败时保留 ID并记录错误，不中断其他用户或服务器。
8. 仅更新 `pending_cleanup_server_ids`，不修改 `last_synced_at`，避免影响用户修改绑定的冷却时间。
9. 当 `server_ids` 和 `pending_cleanup_server_ids` 都为空时删除整条记录；否则保存剩余待清理 ID。

## 异常与并发

- 单个用户或服务器失败不终止整批任务，下一天继续重试。
- XUI 队列只负责后台任务串行；按用户互斥继续覆盖定时清理与手动绑定、解绑的竞争窗口。
- 清理任务内部仍允许同时处理同一用户绑定的不同服务器；不同用户按现有批量循环顺序处理，不扩大为全局持久化锁。
- JSON 数据损坏时跳过该记录并记录错误，禁止把异常数据当作空数组删除。
- 写回前在短事务内锁定并重新读取路由记录，只从最新待清理集合中移除本次已确认清理的 ID，避免覆盖用户同时修改产生的新状态。
- 不在数据库事务中执行 3X-UI 网络请求，避免长时间持有数据库行锁。
- 任务沿用当前 `home_proxy_tag` 删除 routing；历史 tag 变化问题不在本次范围内。

## 代码改动

- 修改 `server/jobs/handlers/clean-pending-home-routes.js`：每天 12:00 将清理任务加入 `xuiJobScheduler`，队列执行时调用服务并输出汇总日志。
- 修改 `server/jobs/index.js`：注册任务并补充任务表说明。
- 修改 `server/repositories/user-home-routing-repository.js`：查询待清理记录，以及在事务中安全移除已完成的 ID。
- 修改 `server/services/shared/home-routing-service.js`：增加批量清理入口，复用现有单服务器 routing 删除逻辑。
- 增加或扩展 `server/test/` 下的相关测试脚本。

## 日志与结果

每次执行记录扫描用户数、成功清理服务器数、离线跳过数、失败数和总耗时。失败日志包含用户、服务器 ID、服务器名称和错误信息，但不记录 API token 等敏感信息。

## 验收标准

- 在线服务器的残留 routing 删除成功后，对应 ID 从待清理字段移除。
- 在线删除失败或服务器离线时，对应 ID 仍被保留。
- 已删除服务器的残留 ID 可以安全移除。
- 已重新绑定的服务器不会被定时任务误删。
- 两个服务器 ID 字段均为空时，本地路由记录被删除。
- 一个用户失败不影响后续用户处理。
- 定时任务仅在北京时间每天 12:00 执行，服务启动时不立即执行。
- cron 到点后只负责入队；routing 清理与其他 XUI 后台任务不会同时运行。
- 同名 routing 清理任务已运行或排队时不会重复加入队列。
- 按用户互斥继续生效，手动换绑不会被定时清理的旧快照覆盖。
