# 管理端家宽 routing 残留清理手动入口设计

## 目的

在管理端家宽 IP 管理页面提供“清理残留路由”按钮，使管理员可以在不等待每天 12:00 定时任务的情况下，将同一个家宽 routing 残留清理任务加入现有 XUI 串行队列等待执行。

## 范围

- 在“添加家宽 IP”按钮右侧增加“清理残留路由”按钮。
- 增加一个需要管理员认证的家宽 IP 管理接口，用于提交清理任务。
- 定时任务和手动接口复用同一个入队方法及同一个任务名称。
- 返回任务成功入队或因同名任务已存在而自动合并的提示。
- 增加对应后端测试，并执行管理端构建验证。

不增加任务进度、历史记录、取消任务、确认弹窗，也不改变 routing 清理业务、定时执行时间或 XUI 队列规则。

## 方案选择

考虑了以下方案：

1. 在家宽 IP 管理模块增加专用接口，由定时任务处理器导出统一入队方法，定时触发和手动触发共同复用。领域归属清晰、改动范围小，并能保证两种入口行为一致。
2. 将手动入口放入服务器管理接口。可以少增加一个路由模块入口，但会让家宽 IP 页面依赖服务器管理领域，职责不清晰。
3. 增加通用后台任务提交接口。扩展性更强，但需要设计任务白名单和通用响应，超出本次需求。

采用方案 1。

## 交互与执行流程

1. 管理员点击“清理残留路由”。
2. 按钮进入 loading 状态并显示“提交中”，防止当前页面重复点击。
3. 前端调用 `POST /api/admin/home-proxies/cleanup-routes/run`。
4. 后端通过统一入队方法向 `xuiJobScheduler` 提交 `home-routing-pending-cleanup` 任务。
5. 如果同名任务尚未运行或等待，则成功加入队列；如果同名任务已经运行或等待，则由现有队列自动合并。
6. 前端显示后端返回的入队或合并提示，并恢复按钮状态。任务按队列顺序在后台执行，接口不等待清理完成。

## 代码改动

- `server/jobs/handlers/clean-pending-home-routes.js`
  - 增加并导出统一的清理任务入队方法。
  - 现有每天 12:00 的 cron 回调改为调用该方法，保持执行时间和业务逻辑不变。
- `server/services/admin/home-proxies-service.js`
  - 增加管理员提交清理任务的方法，返回 `queued`、`merged` 和中文提示。
- `server/controllers/admin/home-proxies-controller.js`
  - 增加手动提交接口控制器。
- `server/routes/admin/home-proxies.js`
  - 注册经过管理员认证的 `POST /cleanup-routes/run` 路由，并确保它位于 `/:id` 动态路由之前。
- `client-admin/src/api/index.js`
  - 增加管理端提交家宽 routing 清理任务的方法。
- `client-admin/src/views/HomeProxies.vue`
  - 在添加按钮右侧增加手动清理按钮、提交状态和消息反馈。
- `server/test/`
  - 覆盖首次入队、同名任务合并、接口响应以及 cron 和手动入口复用同一调度方法。

## 异常处理

- 请求提交失败时沿用管理端现有 API 错误处理，按钮必须恢复可点击状态。
- 同名任务已存在不是错误，返回成功响应并明确提示已自动合并。
- 清理任务的服务器离线、远端删除失败等情况仍由现有清理逻辑处理，不由手动提交接口展开或返回。

## 验收标准

- “清理残留路由”按钮显示在“添加家宽 IP”右侧，移动端沿用现有工具栏纵向布局。
- 点击后只提交任务到现有 XUI 队列，不绕过队列直接执行。
- 手动触发和每天 12:00 的定时触发使用相同任务名称与相同入队方法。
- 同名任务已运行或排队时不重复入队，并向管理员显示自动合并提示。
- 提交过程中按钮显示 loading，成功或失败后均恢复。
- 不影响现有家宽 IP 增删改、手动同步和 routing 清理逻辑。
